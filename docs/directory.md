# The boson directory (`directory` profile)

The directory is the list of IRC networks the boson app's server browser
shows ([boson-chat/directory](https://github.com/boson-chat/directory)).
`https://directory.boson.chat` is the main one; any stack can run its own:

- a website at `https://DIRECTORY_HOST` to browse networks, and for
  owners (signed in with this stack's accounts) to list, verify and edit
  theirs;
- a paginated JSON API (`GET /v1/networks?q=&lang=&tag=&sort=&limit=&cursor=`
  → `{networks, next_cursor, total_estimate}`) and
  `/.well-known/boson-directory.json`, which the app and other
  directories use to find and label it;
- DNS trust: a network is listed only while its `_boson.<hostname>` TXT
  record holds `boson-verify=<token>`. The directory checks it with three
  public resolvers, re-checks it daily, and hides a listing after 14 days
  without a successful check (it comes back when the record does);
- federation: it imports the listings of other directories (peers), and
  shows each one only after checking that network's TXT record itself.

People add directories in the boson app (Settings), so a stack's directory
is useful on its own, and its listings reach directory.boson.chat users
when that directory peers with it.

## Turning it on

The profile needs `auth` (its database lives in the stack Postgres, and
owners sign in with the stack's accounts).

1. `.env`: add `directory` to `COMPOSE_PROFILES`, and check
   `DIRECTORY_HOST` (default `directory.$DOMAIN`), `DIRECTORY_DB_PASSWORD`
   and `DIRECTORY_INTERNAL_TOKEN` (`scripts/setup.sh` writes all three;
   generate the secrets with `openssl rand -hex 32` otherwise).
2. Add `DIRECTORY_HOST` to `CERT_HOSTS` and point its DNS at the server.
3. Existing installs: create the database once (below).
4. `docker compose up -d`.

The admin panel talks to it when `ADMIN_DIRECTORY_LOCAL_URL=http://directory:8080`
is set (setup.sh does it with the profile); see "Admin panel" below.

### Existing installs: sign-in from the web UI

The directory's web UI signs people in against auth from the browser, so auth
must allow the directory's origin. setup.sh sets this with the profile; on an
existing install add to `.env` and recreate auth:

```sh
AUTH_CORS_ALLOWED_ORIGINS=https://directory.example.com
```

### Existing installs: the database

`postgres/initdb/20-directory.sh` only runs when the Postgres volume is
created. On an install that already has data, create the database once:

```sh
P=$(grep ^DIRECTORY_DB_PASSWORD= .env | cut -d= -f2-)
docker compose exec -T postgres psql -U auth -d postgres \
  -v pw="$P" -v usr=directory -v db=directory <<'SQL'
CREATE ROLE :"usr" LOGIN PASSWORD :'pw';
CREATE DATABASE :"db" OWNER :"usr";
SQL
```

The directory applies its own migrations when it starts.

## Settings

**Change the directory's name, operator, contact, main-directory switch,
sync interval and peers in the admin panel** (Directory page → "Your own
directory"; needs directory ≥ 1.4.0 and admin ≥ 1.7.0). The directory
stores them in its own database and applies them at once, without a
restart, and they survive restarts. The `.env` values marked *default* below
only seed a fresh directory: once a value is changed in the panel, the
panel's value wins until it is reset (`PATCH /v1/admin/settings` with
`null`). Secrets and infrastructure (database, token, hostnames, image)
stay in `.env`.

| Variable | Default | |
|---|---|---|
| `DIRECTORY_HOST` | `directory.$DOMAIN` | public hostname (add it to `CERT_HOSTS`) |
| `DIRECTORY_IMAGE` | `harbor.floret.dev/boson/directory:1.3.0` | |
| `DIRECTORY_INCLUDE_MAIN` | `true` | *default*: your directory also shows everything from directory.boson.chat; `false` = an independent directory |
| `DIRECTORY_MAIN_PEER` | `https://directory.boson.chat` | *default*: the built-in main peer |
| `DIRECTORY_PEERS` | – | more directories to import, comma-separated base URLs; each is seeded once on first start (a peer removed later stays removed) |
| `DIRECTORY_NAME` | `$NETWORK_NAME directory` | *default*: shown in `/.well-known/boson-directory.json` and the app's source badge |
| `DIRECTORY_CONTACT` | `$ADMIN_EMAIL` | *default*: operator contact in `/.well-known/boson-directory.json` (the operator defaults to `$NETWORK_NAME`) |
| `DIRECTORY_DB_PASSWORD` | – | generated by `scripts/setup.sh` |
| `DIRECTORY_DB_NAME`, `DIRECTORY_DB_USER` | `directory` | |
| `DIRECTORY_INTERNAL_TOKEN` | – | operator API token (`X-Internal-Token`), shared with the admin panel |
| `DIRECTORY_SERVES_LEGACY` | `false` | `true` routes `https://API_HOST/servers*` to the directory (cutover, below) |
| `DIRECTORY_LOG_LEVEL` | `info` | |
| `DIRECTORY_ENV`, `DIRECTORY_DNS_VERIFIER` | `production`, real DNS | testing only: `development` + `fake` makes every TXT check pass (CI) |

Icons and banners are stored in the `directory_media` volume; back it up
with `pg_data`.

## Including the main directory

By default a new directory is not empty: it has directory.boson.chat as a
built-in, enabled peer and imports its listings every 10 minutes. Each
imported network shows up only after your directory has checked its TXT
record itself, so a peer can't vouch for a network that doesn't hold the
record. Your own (local) listings win over a peer's listing of the same
hostname.

To run an independent directory, switch **Include the boson main
directory** off in the admin panel (Directory page). It applies at once (the
imported listings disappear) and is kept across restarts; switching it back
on recreates or re-enables the main peer straight away, again without a
restart. `DIRECTORY_INCLUDE_MAIN=false` in `.env` only sets the default for
a directory nobody has switched yet.

directory.boson.chat itself has no main peer (it would be peering with
itself): when `DIRECTORY_MAIN_PEER` is the directory's own URL, the admin
panel says "This is the boson main directory — other directories include
it" instead of showing the switch.

## Peering

Add other directories in the admin panel (Directory page → "Other
directories": paste the URL, check, add; enable/disable, sync now, remove),
or on the directory's own Peers page signed in with `directory.manage`.
`DIRECTORY_PEERS` only seeds a fresh install. The directory reads each peer's
`/.well-known/boson-directory.json`, then pulls its `/v1/feed` every 10
minutes from the last position. Only public listing data and verification
tokens are exchanged, never accounts or network keys. Blocks you add on
the Blocks page apply to every source.

For directory.boson.chat (or anyone else) to show your directory's
listings, they add your `https://DIRECTORY_HOST` as a peer.

## Listing a stack network (admin panel)

The admin panel's **Directory** page lists the network in
`ADMIN_DIRECTORY_API_URL` (default `https://directory.boson.chat`) without a
boson.chat account: the panel signs its requests with a network key
(`Authorization: Network <key>`, derived from `ADMIN_SESSION_KEY` and the
hostname; the directory stores only its hash) and the page walks you
through the `_boson.<IRC_HOST>` TXT record and the check. To list it in your
own directory instead, set `ADMIN_DIRECTORY_API_URL=http://directory:8080`.
`ADMIN_DIRECTORY_REGISTRATION=false` turns registration off (the page then
only reports whether the network is listed).

With `ADMIN_DIRECTORY_LOCAL_URL=http://directory:8080` and
`DIRECTORY_INTERNAL_TOKEN`, the page also shows "Your own directory" (the
include-main switch, the directory's name/operator/contact and sync
interval, and its peers), and each user's page lists the networks they
registered there. Both need admin ≥ 1.5.0 (the `/v1` directory API);
changing the settings and managing peers from the panel needs admin ≥
1.7.0 with directory ≥ 1.4.0 (older directories get a note, and the switch
only toggles an existing main peer).

## Legacy `/servers` route

Before the directory existed, the server directory was part of the boson
API (`api` profile): `GET/POST/PATCH https://API_HOST/servers…`, used by
boson client ≤ 0.45, the website and old links. The directory serves the
same paths with the same shapes. With `DIRECTORY_SERVES_LEGACY=true`,
`traefik/dynamic/directory.yml` adds a router for `Host(API_HOST) &&
PathPrefix(/servers)` to the directory, above the api router; everything
else on `API_HOST` still goes to the api. With `false` (the default) the
file defines nothing. Traefik reads the variable from its environment, so
apply a change with `docker compose up -d traefik`.

## Cutover from the api directory

For an install whose server directory lives in the `api` profile today
(boson.chat):

1. DNS for `DIRECTORY_HOST`, add it to `CERT_HOSTS`, create the database
   (above), add `directory` to `COMPOSE_PROFILES`, `docker compose up -d`.
   Check `https://DIRECTORY_HOST/.well-known/boson-directory.json`.
2. Dry run the import from the api database. It copies `servers` into the
   directory, maps `registered_by` to boson accounts, normalises hostnames
   and resolves duplicates (verified first, then the oldest), and prints
   what it would do:

   ```sh
   A=$(grep ^API_DB_PASSWORD= .env | cut -d= -f2-)
   docker compose run --rm directory import-legacy \
     --from "postgres://api:$A@postgres:5432/api?sslmode=disable" --dry-run
   ```

3. Review the output, then run it again without `--dry-run`.
4. Switch the legacy route: `DIRECTORY_SERVES_LEGACY=true` in `.env`,
   `docker compose up -d traefik`. Check
   `curl https://API_HOST/servers?limit=2` (old shape, now from the
   directory) and `curl "https://DIRECTORY_HOST/v1/networks?limit=2"`, then
   follow `next_cursor`.
5. Admin panel: the Directory page lists the network from the new
   directory.

Rolling back is step 4 in reverse (`DIRECTORY_SERVES_LEGACY=false`): the api
still has its `servers` table.

**Afterwards:** the api's `api-cron` jobs (`cron --mode=verify` and
`--mode=health`) and the backend's directory code have been removed; run
`docker compose up -d --remove-orphans` once to remove the old `api-cron`
container. The api's `servers` table is kept for one release for rollback,
so step 4 in reverse still works with an api image from before the removal.
