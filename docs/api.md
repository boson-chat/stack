# The boson API (`api` profile)

The backend the boson client talks to: profiles, nick claims, avatars and
link previews for the web client ([boson-chat/backend](https://github.com/boson-chat/backend)). It's optional; enable it with `api` in `COMPOSE_PROFILES`.

| Service | What it does |
|---|---|
| `api` | `serve` on port 3000, routed by Traefik at `API_HOST` (add it to `CERT_HOSTS`) |
| `api-migrate` | runs `migrate up` before `api` starts, then exits |

The server directory has moved out of the API into its own service,
[boson-chat/directory](https://github.com/boson-chat/directory) (the
`directory` profile; see [directory.md](directory.md)). With
`DIRECTORY_SERVES_LEGACY=true`, `https://API_HOST/servers*` is routed to the
directory, so old clients keep working. The API no longer serves `/servers`
and has no scheduled jobs: the `api-cron` service (`cron --mode=verify` and
`--mode=health`) is gone. On an existing install, run
`docker compose up -d --remove-orphans` once to remove its container. The
api's old `servers` table is kept for one release for rollback.

It reads its `nick_claim:` section from `config/boson.yaml` (mounted
read-only, `BOSON_CONFIG`; [config.md](config.md)) and answers
`/internal/config/status` on its internal port 3001 (compose network only).

It verifies access tokens from the stack's auth service (`AUTH_JWKS_URL`
inside the network, `aud=boson`) and stores data in the stack Postgres, in its
own database and role (`API_DB_NAME` / `API_DB_USER`, default `api`).

## Settings

| Variable | Default | |
|---|---|---|
| `API_HOST` | `api.$DOMAIN` | public hostname |
| `API_IMAGE` | `harbor.floret.dev/boson/backend:0.57.0` | |
| `API_DB_PASSWORD` | – | generated by `scripts/setup.sh` |
| `API_DB_NAME`, `API_DB_USER` | `api` | |
| `API_ALLOWED_ORIGINS` | `https://$DOMAIN` | CORS allow-list (comma-separated) |
| `API_INTERNAL_TOKEN` | – | generated by `scripts/setup.sh`; the admin panel's calls to the api's internal port (`http://api:3001`) |
| `NICK_CLAIM_ENABLED` | `false` | nick claims ([nick-claim.md](nick-claim.md)); default only, `config/boson.yaml` `nick_claim.enabled` wins |
| `NICK_CLAIM_EMAIL_DOMAIN`, `NICK_CLAIM_RATE_LIMIT_PER_HOUR` | `$DOMAIN`, 5 | defaults for `nick_claim.email_domain` / `rate_limit_per_hour` |
| `POP3_HOST/PORT/USER/TLS` | empty, 995, empty, true | defaults for `nick_claim.inbound.*` (the mailbox the worker polls) |
| `NICK_CLAIM_POP3_PASSWORD` (older name: `POP3_PASSWORD`) | – | that mailbox's password; secret, `.env` only |
| `R2_ACCESS_KEY/SECRET_KEY/ENDPOINT/BUCKET`, `CDN_BASE_URL` | empty = off | avatar storage (any S3-compatible store) |
| `API_UNFURL_ENABLED` | `true` | link previews (below) |
| `API_UNFURL_RATE_PER_IP` | `120` | preview fetches a minute per address, for callers that aren't signed in (0 = no cap) |
| `API_UNFURL_RATE_PER_USER` | `60` | preview fetches a minute per signed-in user (0 = no cap) |

## Link previews

The web client (`web` profile, [web.md](web.md)) can't fetch other sites
from the page, so the API does it for it: `GET /v1/unfurl?url=` (website
cards: OpenGraph title, description, image, site, author, date; YouTube
titles) and `GET /v1/unfurl/spotify?url=` (Spotify cards with the track
list). The desktop app fetches these itself and doesn't use them. No sign-in
is needed; signed-in calls are limited per user, others per address (read
from Traefik's `X-Forwarded-For`, trusted only from `STACK_SUBNET`). Answers
are cached for 30 minutes and cached answers don't count.

Because the api container sits on the stack network next to Postgres, auth
and the rest, the fetch is guarded: http/https on ports 80 and 443 only;
every address it connects to (after DNS, so a name that resolves or
re-resolves to an internal address is caught) must be public, never
loopback, private (the stack network), link-local, cloud metadata, CGNAT or
reserved; at most 5 redirects, each checked again; 8 seconds and 1 MiB of
HTML per page; HTML only. It identifies itself as `BosonBot/1.0`. Preview
images are not proxied: the client loads them from their own (https) URLs.

## Existing installs

`postgres/initdb/10-api.sh` only runs when the Postgres volume is created. On
an install that already has data, create the database once:

```sh
P=$(grep ^API_DB_PASSWORD= .env | cut -d= -f2-)
docker compose exec -T postgres psql -U auth -d postgres \
  -v pw="$P" -v usr=api -v db=api <<'SQL'
CREATE ROLE :"usr" LOGIN PASSWORD :'pw';
CREATE DATABASE :"db" OWNER :"usr";
SQL
```
